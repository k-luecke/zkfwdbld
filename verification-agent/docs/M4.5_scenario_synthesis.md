# M4.5 — Scenario synthesis (turn a found path into a verdict)

> **State: IMPLEMENTED** (self-contained pipeline + Control anti-rigging guarantee;
> deploy-graph *discovery* proven execution-correct on a true positive) /
> **FRONTIER** (the "semantic mile" — mock behaviour, call payloads, and the core
> blocker: autonomous signature construction for the honest Control).
> Deploy-graph synthesis turned out to be the tractable minority; the semantic
> mile is the real distance to a blind catch.
> Demo: [`examples/m45_synthesis.txt`](../examples/m45_synthesis.txt)
> (+ [`.json`](../examples/m45_synthesis.json)).

M6 produced the diagnosis: the loop *surfaces* the right blind findings and Seer
*leads* on the real ones, but Tier-1 blind = 0 because nothing converts a lead
into a gate verdict without a hand-built scenario. M4.5 is the named component
that closes that gap — and it is a different kind of milestone, because for the
first time the system is *generating* the scenario, which is where the
hallucination risk re-enters. So the build is organized around the discipline,
not the demo.

## The discipline first: synthesized scenarios get no fast path

The gate ([VerifyGate.sol](../verification_agent/verify/solidity/VerifyGate.sol))
does not know or care whether a human or the machine wrote the scenario. A
synthesized scenario is dropped next to the **byte-for-byte real** `VerifyGate.sol`
and judged by the same four-phase `testGate` (baseline → control → attack →
verdict). The runner ([runner.py](../verification_agent/synthesize/runner.py))
copies the actual gate file — not a reimplementation — so "the same gate" is
literally true, and the synthesizer never sets a verdict.

This matters because generation introduces a new failure mode: a machine could
synthesize a scenario that "works" by being *wrong* — a harness subtly rigged so
the invariant breaks for a reason that isn't the real bug (the M4.5 version of
the wrong-reason catch). The defense already exists: **Control**. A synthesized
scenario must pass baseline *and* control (a legitimate action preserves the
invariant) before any attack runs. If a synthesized predicate can only "break"
by being too brittle, Control rejects it.

We prove this rather than assert it. From every structural lead the synthesizer
generates **two** scenarios:

| Generated case | Invariant | Through the real gate |
|---|---|---|
| **faithful** | every privileged effect was authorized (`effectCount == authorizedEffects`) | **CONFIRMED** |
| **rigged-control** | `effectCount == 0` — any honest use breaks it | **REJECTED_MALFORMED_CONTROL** |

```
[lead] receiveFromBridge  (bypasses retrieveAndCollectFees)
   mechanism=access-control/alt-entrypoint  executable=True  self_contained=True
   [OK ] faithful       -> CONFIRMED                    (expected CONFIRMED)
   [OK ] rigged-control -> REJECTED_MALFORMED_CONTROL   (expected REJECTED_MALFORMED_CONTROL)
```

The rigged case is the load-bearing result: **a machine-written rigged predicate
is caught by Control exactly as a human's would be.** That is what keeps
machine-written scenarios honest.

## The template is target-agnostic (so a CONFIRM can't be smuggled)

The synthesis template ([templates.py](../verification_agent/synthesize/templates.py))
carries **no protocol names and no hand-encoded deploy steps**. It is filled only
from the structural shape of a Seer lead — the unguarded entrypoint and the guard
it bypasses — and generates a self-contained reproduction of the
alt-entrypoint-gated-effect mechanism: a privileged sink reached by a guarded
sibling *and* the unguarded entrypoint, the independent authorized-effect
invariant, an honest control, and the attack. A test asserts no protocol name
leaks into the generated source, so a `CONFIRMED` cannot have been rigged by
smuggling the answer into the template.

The gate the unguarded path bypasses may be an access modifier (`onlyOwner`) **or
a value/fee/signature collection gate** the path skips entirely — Decent M-03's
`retrieveAndCollectFees` is the latter, and it is the canonical structural
reproduce target, not a signature-scope bug.

## What it does NOT claim: the honest boundary

A self-contained scenario proves the **pipeline** and the **Control guarantee**.
It does **not** certify a real finding, and the synthesizer says so in
[`SynthScenario.executable` / `.gap`](../verification_agent/synthesize/schema.py).
Two boundaries are enforced ([synthesizer.py](../verification_agent/synthesize/synthesizer.py)):

1. **Self-contained ≠ real.** Only execution against the *real deployed code* can
   certify a finding, because only the real code says whether the unguarded
   sibling truly exists and truly reaches the sink unauthorized. The self-contained
   run models the *structure the lead asserts*; certifying the lead needs the
   protocol's deploy graph synthesized.

2. **Mechanism fit.** The structural template would *misrepresent* a
   signature/permit-scope bug, where the guard is not absent but satisfied by a
   signature whose scope is the flaw. The two blind Centrifuge leads
   (`requestRedeemWithPermit` / `requestDepositWithPermit`) are exactly this, so
   the synthesizer classifies them **non-executable** with the gap named — refusing
   to force them through a template that would confirm a bug that isn't the real
   one. That refusal is the synthesizer being honest about its own limits.

```
[lead] requestRedeemWithPermit  (bypasses withApproval)
   mechanism=signature-scope  executable=False
   NOT EXECUTABLE — honest gap: ... the guard is satisfied by a signature whose
   SCOPE is the bug (a permit not bound to the pool, replayable cross-pool). A
   faithful scenario needs the real protocol deployed + EIP-712 permit construction
   + a scope invariant — autonomous deploy-graph + signature synthesis is the frontier.
```

## What this means for the backtest

**Blind Tier-1 stays 0.** M4.5 has proven the conversion *pipeline* and the
*anti-rigging guarantee*, but converting the specific blind Centrifuge leads into
real blind CONFIRMEDs needs the next component: autonomous real-protocol
deploy-graph synthesis (and EIP-712 construction for the permit leads). The number
the operator reads does not move until a synthesized scenario confirms a real
finding against real code — and that honesty is the point: the same backtest that
said "not yet" is the one that will say "now."

## Deploy-graph synthesis on a true positive (Decent M-03)

The next layer attacks the named gap directly: can the real-protocol deploy graph
be derived from the M0 model? Run against a *true-positive* structural bug (Decent
M-03), `DeployGraphSynthesizer` ([deploygraph.py](../verification_agent/synthesize/deploygraph.py))
reads the target's owner-gated wiring setters from the model and matches each to a
collaborator by type/name, emitting a deploy+wiring backbone. Spliced into a
hand-built semantic mile and run through the unchanged gate, it **CONFIRMS against
real Decent code** (calibration) — proving the machine-generated backbone is
execution-correct. Recorded run: [`examples/m45_deploygraph_decent.txt`](../examples/m45_deploygraph_decent.txt),
evidence scenario [`examples/synthesized/DecentM03DeployGraph.t.sol`](../examples/synthesized/DecentM03DeployGraph.t.sol).

**But the measurement is the result, not the CONFIRMED.** The autonomy ledger,
kept honestly:

- **Machine-derived:** the collaborator set + owner-gated wiring; a 6-line
  deploy+wiring backbone. **5 of 6 lines fully autonomous.** One needed a hand-fix:
  `setFeeCollector` wants `address payable`, but the Slither-normalized model
  records `setFeeCollector(address)` — the `payable` qualifier is lost, so the
  synthesizer can't know to emit the cast (a model-fidelity gap). Candidate
  matching was also over-inclusive (picked heavy concretes like `UniSwapper` that
  need *their own* deploy graphs); selecting the path-relevant, deployable subset
  was a hand judgment.
- **Hand-built (the "semantic mile", not model-derivable):** mock *behaviour*
  (a swapper that returns the fee token; a mintable token; the sink), ownership /
  collaborator-side wiring, funding, the call payloads, and — the core blocker —
  a **valid signature** for the honest control.

**This is not an autonomous catch.** It is a machine-generated backbone spliced
into a hand-built mile, CONFIRMED on real code, calibration. It does not change the
live-contest decision; it proves the infrastructure on a true positive and measures
the distance left.

### The frontier, sharpened

The premise that "deploy graph" was *the* missing capability is itself refined:
deploy-graph **discovery** is the tractable, mostly-autonomous part — and a
*minority* of a confirming scenario. The dominant frontier is the **semantic
mile**, and for this bug class its core is **autonomous signature construction for
the honest Control**. Even a perfect deploy graph cannot reach an autonomous
CONFIRMED on M-03 without it: with no valid signature the Control reverts
(`REJECTED_MALFORMED_CONTROL_REVERT`), and the gate refuses to judge the attack.

## An honest negative result: the Centrifuge structural leads

Kept as a first-class artifact ([`examples/m45_centrifuge_refutation.txt`](../examples/m45_centrifuge_refutation.txt),
scenario [`examples/synthesized/CentrifugeRelyLead.t.sol`](../examples/synthesized/CentrifugeRelyLead.t.sol)).
Homework against the real contest source showed the surfaced structural Centrifuge
leads are **design-permissionless functions guarded by preconditions, not
bypasses** — `executeScheduledRely` requires a ward-authorized, time-locked
schedule; `deployLiquidityPool`/`deployTranche` require the `onlyGateway`
`addPool`/`addTranche`. Deploying the real `Root` and running the lead through the
unchanged gate returns **`REJECTED_ATTACK_REVERTED`** (`"Root/target-not-scheduled"`):
the gate refutes the lead against real code, rather than asserting it false.

The real Centrifuge access-control findings (M-06, M-08) were **missed at M0** and
are not unguarded-entrypoint shaped; M-01 is cross-domain *insufficiency*. So the
blind Centrifuge zero is a **bug-class coverage** gap, not a deploy-graph gap — and
the next blind *structural* target is a different contest, not Centrifuge. A system
that records what it proved false against real code is more trustworthy than one
that only logs wins.

## Run it

```bash
# deploy-graph synthesis + autonomy ledger for a target:
python -m verification_agent synthesize --deploygraph examples/2024-01-decent.model.json --target UTB

python -m verification_agent synthesize --demo --workspace ./synth_ws \
       --json examples/m45_synthesis.json
# or a single lead:
python -m verification_agent synthesize \
       --entrypoint receiveFromBridge --guard retrieveAndCollectFees --workspace ./synth_ws
```

Requires `forge` and a workspace with `forge-std` (auto-provisioned). No protocol
clone is needed — the self-contained scenario generates its own target.

## Scope discipline

Forks and fixtures only, as everywhere else. The synthesized scenarios run in an
isolated, generated workspace — never against a live deployment.
